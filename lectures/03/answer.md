## 宿題

### 取り組んだレベル
基礎

### やったこと
同じ質問「LoRA とQLoRAの違いは？」を `uv run python -m app.agent --trace` で実行し、
1か所ずつ変更して、ツールの呼ばれ方と回答がどう変わるかを比べた。

1. 変更前(ベースライン)
2. `app/tools.py` の `search_glossary` の docstring を「用語を1つだけ入れる」→「まとめて入れる」に変更
3. docstring を元に戻し、`app/agent.py` の INSTRUCTIONS から
   「用語や講座に固有のことを答える前に、必ず search_glossary で用語集を確認する」の行を削除(3回実行)

### 結果

| 条件 | ツール呼び出し | tool_calls | requests | 入力トークン |
|---|---|---|---|---|
| 変更前 | search_glossary('LoRA') と ('QLoRA') の2回 | 2 | 2 | 1196 |
| docstring「まとめて」 | search_glossary('LoRA QLoRA') の1回 | 1 | 2 | 885 |
| INSTRUCTIONSの1行削除(3回) | 変更前と同じ2回 | 2 | 2 | 1148 |

- docstring を変えると、検索が2回から1回にまとまった。
- 一方で requests は2のまま。ツールを1回呼ぶだけでも「質問→ツール呼び出し→結果を見て回答」でLLMを2回呼ぶため。
- INSTRUCTIONS の1行を消しても、3回とも変更前と同じく2回に分けて検索した。入力トークンは1196→1148に減ったので、変更はモデルに渡っている。
- 回答の内容は用語集の定義と矛盾せず、最後に「第2回」が付いた。ただし1回だけ「第2回（第2回）」という表記の崩れがあった。

### 気づき・疑問
- モデルはツールの docstring を読んで、引数の渡し方を決めている。1語の違いで呼び出し方が変わった。
- INSTRUCTIONS の1行を消しても動きが変わらなかった。理由は、docstring に「答える前に使うこと」と
  書かれていて、同じ役割を担っているのかもしれない。docstring 側を消す実験は未実施。
- 「LoRA QLoRA」と1つにまとめて検索したとき、QLoRAの説明は回答に入っていたので、モデルが自分の知識で補った可能性がある。
- 各条件は1〜3回の実行しかしていないため、毎回同じ傾向かは言い切れない。
